## glp1-service-spec-plan - 2026-04-16

- [ ] 게스트 모드 허용 범위 — 로그인 없이 클리닉 검색/가이드 열람을 허용할지, 아니면 앱 진입 시 반드시 로그인을 요구할지. 게스트 허용 시 전환율에 영향, 미허용 시 이탈률에 영향
- [ ] 하단 탭 5개 구성 확정 — 현재 ホーム/記録/クリニック/ガイド/マイ 5탭으로 설계했으나, "記録" 탭에 투약+체중+부작용이 모두 들어가면 복잡해질 수 있음. "投薬"과 "体重"을 분리할지 결정 필요
- [ ] 주사 부위 로테이션 맵의 시각적 표현 방식 — 인체 일러스트(복부/허벅지/상완) 위에 마커를 찍는 방식 vs 단순 리스트 선택 방식. 일러스트 방식은 UX가 좋지만 에셋 제작 비용이 있음
- [ ] 약동학(PK) 곡선 계산의 정확도 기준 — Shotsy처럼 임상 데이터 기반 정밀 계산 vs 반감기 기반 단순 근사치. 정밀 계산은 의학 자문이 필요하고, "의료기기" 분류 리스크가 높아질 수 있음
- [ ] WatermelonDB vs SQLite(expo-sqlite) 선택 — 기존 기획서에서 WatermelonDB를 언급했으나, Expo 환경에서의 호환성과 동기화 복잡도를 고려하면 expo-sqlite + 자체 동기화 로직이 나을 수 있음. 기술 검증 필요
- [ ] 리뷰 작성 시 실명/닉네임 정책 — 일본 사용자는 익명성을 선호하는 경향이 있으나, 완전 익명 리뷰는 신뢰도가 낮음. 닉네임 + "投薬歴3ヶ月" 같은 경험 배지 표시 방식 검토 필요
- [ ] 가격 제보(UGC) 검증 프로세스의 자동화 수준 — 3명 이상 독립 제보 시 자동 승격하는 규칙이 있으나, 초기 사용자 부족 시 검증이 지연될 수 있음. 관리자 수동 승인 대시보드가 MVP에 필요한지 결정 필요
- [ ] Apple Health 역동기화(앱->Health) 필요성 — 앱에서 기록한 체중을 Apple Health에 쓰는 기능은 사용자 편의를 높이지만, 다른 앱과의 데이터 충돌(무한 루프) 가능성이 있음. 읽기 전용으로 시작할지 결정 필요
